# 教师备课工具包

## 包含模块

| 模块 | 触发词 | 详细规则 |
|------|--------|---------|
| 教案生成 | `教案` `教学设计` `课堂设计` `备课` `生成教案` `写教案` | `modules/lesson-plan.md` |
| 分层练习 | `出题` `练习` `测验` `检测` `作业` `试卷` `题目` `口算` | `modules/quiz.md` |

## 何时使用

当用户要求生成教案、教学设计、练习、作业、试卷等备课相关任务时使用本技能。

## 模块路由

1. 根据用户意图和触发词判断使用哪个模块。
2. 读取 `$SKILL_ROOT/modules/lesson-plan.md` 或 `$SKILL_ROOT/modules/quiz.md`。
3. 先执行本文件中的"共享流程"，再按模块规则生成。

如果用户同时需要教案和配套练习，先完成一个模块，完成后提示可以继续使用另一个模块。

## 共享流程

以下规则适用于两个模块。

### 第零步：确认 SKILL_ROOT

在读取或保存任何参考材料之前，先确定 `SKILL_ROOT`，后续所有路径都必须解析为这个根目录下的绝对路径。

判定规则：

1. 如果用户明确要求使用某个项目内的 Skill，或用户提供的任务文件位于某个项目目录，且该项目下存在 `skills/edu-toolkit/SKILL.md`，则：
   - `SKILL_ROOT = <该项目>/skills/edu-toolkit`
   - 参考资料必须读写到 `<该项目>/skills/edu-toolkit/references/`
   - 不要写入 `~/.workbuddy/skills/edu-toolkit/`
2. 只有在用户没有指定项目内 Skill，且当前任务确实是使用 WorkBuddy 已安装 Skill 时，才使用：
   - `SKILL_ROOT = ~/.workbuddy/skills/edu-toolkit`
3. 开始处理前，用 `ls "$SKILL_ROOT/SKILL.md"` 验证目录存在。
4. 对话中涉及保存路径时，必须报告绝对路径，不能只写相对路径。

### 参考资料目录结构

```
$SKILL_ROOT/
├── SKILL.md
├── modules/
│   ├── lesson-plan.md     ← 教案生成规则
│   └── quiz.md            ← 分层练习生成规则
├── references/
│   ├── 课标/              ← 【只读】课程标准摘要，不因教师操作改变
│   ├── 课本内容/          ← 【可写】教师发来的课本素材整理后存这里
│   ├── 教案参考/          ← 预置 + 教师可添加自己觉得好的教案
│   └── 练习参考/          ← 预置 + 教师可添加自己觉得好的练习/试卷
└── scripts/
    ├── read_reference.py  ← 统一读取参考资料
    ├── to_docx_lesson.py  ← 教案 Markdown → Word
    └── to_docx_quiz.py    ← 练习 Markdown → Word
```

- **课标** 是静态资料，生成时只读取、不修改、不往里添加新文件。
- **课本内容** 是动态资料，教师每次发来新的课本页面，识别整理后保存到这里，两个模块共用。
- **教案参考** 和 **练习参考** 存放教师提供的、教材配套的、学校真实使用的、或人工审核通过的优秀范例。不要把本 Skill 自己生成的历史产物放入这些目录，也不要把它们当作参考读取；这类文件会把旧结构和错误偏好带入新生成。

### 支持的参考材料格式

| 格式 | 可靠程度 | 处理方式 |
| --- | --- | --- |
| `.md` / `.txt` | ✅ 100% 可靠 | 直接读取 |
| `.docx` | ✅ 可靠 | 通过 markitdown / python-docx 解析（缺库时自动安装） |
| `.pdf` | ✅ 可靠 | 通过 markitdown / PyPDF2 解析（缺库时自动安装） |
| `.pptx` | ✅ 可靠 | 通过 markitdown 解析（缺库时自动安装） |
| `.png` / `.jpg` | ⚠️ 看模型 | 需要多模态模型才能识别 |

教师发来的 Word、PDF、PPT 文件都能直接处理，不需要转格式。使用 `scripts/read_reference.py` 统一读取：

```bash
cd "$SKILL_ROOT"
python3 scripts/read_reference.py "文件或目录路径"
python3 scripts/read_reference.py "文件路径" --extract-images   # 提取嵌入图片
python3 scripts/read_reference.py "目录路径" --all               # 读取目录中所有文件
```

脚本会自动检测有哪些解析库可用。读不了的格式会给出提示而不是报错。运行不带参数可查看完整用法。

共享 Skill 中统一使用 `python3` 作为示例命令。不要把某台机器的绝对 Python 路径写入提示词；如果本地环境遇到依赖或代码签名问题，应在本机运行时临时指定已验证可用的解释器。

### 图片/扫描件读取失败时必须暂停

如果教师提供的是课本照片、截图、图片文件、扫描版 PDF，或脚本导出的嵌入图片，而当前模型/工具无法可靠读取图片内容：

1. **立即暂停当前任务，不要继续生成。**
2. 明确告诉教师：当前模型无法读取图片内容，需要切换到支持图像理解的模型后再继续。
3. 建议教师切换到多模态模型（如 Kimi、GLM 等支持图片理解的模型），然后重新发送图片或扫描件。
4. 不要根据文件名、上下文、相似课题或已有整理稿猜测图片内容。
5. 不要用旁边的整理稿或其他材料替代，除非教师明确说"可以使用已有整理稿继续"。
6. 图片未成功读取前，禁止输出"已整理保存""已完成处理"等完成性表述。

可直接使用以下提示：

> 我现在无法可靠读取这张图片/扫描版 PDF 的内容。为了避免把内容识别错，我先暂停处理。请把当前模型切换到支持图片理解的模型（如 Kimi、GLM 等），然后重新发送这张图片/扫描件。切换后我会继续把内容整理保存下来。

### 已持久化内容可直接使用

如果课本照片、截图、扫描版 PDF 或图片型材料已经成功识别，并已保存到 `$SKILL_ROOT/references/课本内容/` 下的 `.md` 文件，后续生成教案或练习时应直接读取该 `.md`。这个 `.md` 是已完成持久化的正式课本内容，不属于"旁边的整理稿或其他材料替代"，不需要重新要求教师发送或查看原图。

只有在 `.md` 不存在、内容明显缺漏、与当前课题不匹配，或教师明确要求重新核对原图时，才回到图片/扫描件读取流程。

### SVG 教学素材生成

如果教案或练习中需要**教学功能型图示**（几何图、数轴、统计图、方格图、板书结构图、操作示意图、流程图等），可生成 SVG。

#### 适合生成

- 数学：几何图形、数轴、方格图、点子图、统计图、坐标图、分类树、流程图
- 科学：实验装置示意图、观察记录图、过程箭头图
- 语文/英语：结构图、情节流程图、人物关系图、句式支架图
- 练习题：读图题、统计图题、几何题、操作题所需图形
- 教案：板书结构图、课堂操作示意图、探究流程图

#### 不生成

- 只为美化页面的装饰图
- 人物、校园、食堂、风景等真实场景图
- 大模型生成图片、插画、照片或位图素材
- 课本原图已经足够，且不需要重画或抽象化的图
- 会挤占学生作业两页版空间的非必要图

> 核心原则：SVG 必须服务于教学理解或题目作答；不能为了装饰生成 SVG。

#### 生成前判断

生成任何 SVG 前，先做需求判断：

```text
本次 SVG 判断：
1. 素材名称：……
   结论：需要生成 / 可选 / 不生成
   理由：……
   用途：教案板书 / 课堂活动 / 学生练习 / 教师答案 / 课件参考
```

- **必须生成**：学生需要看图才能答题，或教师需要图示才能组织核心活动。
- **可以生成**：图能明显降低理解难度，但没有它也能完成教学。
- **不生成**：只是情境装饰、版面美化、重复课本已有图片，或会挤占作业空间。

#### 教案中的 SVG 规则

- 可自动生成板书图、统计图模板、操作图或流程图。
- 可选辅助图只在教师使用建议中列出，不强行生成。
- 单份教案中 SVG 建议控制在 1-3 个，避免喧宾夺主。

#### 练习中的 SVG 规则

- 只有题目必须依赖图形时才生成 SVG。
- 学生作业版严格两页，SVG 不能挤占必要题目空间。
- 如果图较复杂，应放入教师版或改成更小的读图素材。
- 每个 SVG 题必须保证学生能独立读图作答，不依赖另一页信息。

#### SVG 技术要求

- 必须包含 `xmlns="http://www.w3.org/2000/svg"` 和 `viewBox`。
- 不使用外部图片、外部字体、远程资源或脚本。
- 不生成光效、渐变装饰、复杂阴影等非教学元素。
- 文字字号不小于 12px，线条和箭头清晰，黑白打印也能辨认。
- 颜色只用于区分信息，不依赖颜色传达唯一含义。
- 图中所有文字必须准确、简短，不写大段说明。
- 常用尺寸：练习题小图 `viewBox="0 0 420 260"`，半页图 `viewBox="0 0 720 420"`，板书/流程图 `viewBox="0 0 900 520"`。

#### SVG 保存与验证

保存到 `assets/generated/svg/{课题或知识点}/{素材名}.svg`，Markdown 中用图片路径引用。

生成 Word 时，不要依赖 Word 直接嵌入 SVG。转换脚本应先把 SVG 渲染为 PNG，再将 PNG 嵌入 Word。

生成后必须验证：

1. 文件确实存在。
2. SVG 能被读取，包含 `<svg`、`viewBox` 和闭合 `</svg>`。
3. 无外部资源引用，如 `http://`、`https://`、`<script>`。
4. 关键文字、数据、单位、题号没有错误。
5. 如果用于学生两页作业，确认不会破坏两页结构。

```bash
test -f "assets/generated/svg/课题/素材名.svg"
rg -n "<svg|viewBox|</svg>|http://|https://|<script" "assets/generated/svg/课题/素材名.svg"
```

### 课本材料的持久化

教师提供的课本材料（不管来自对话还是本地文件）都应整理成 .md 保存到对应目录：

- 课本页面、教材内容、教材练习、教师用书说明 → `$SKILL_ROOT/references/课本内容/`
- 教师觉得好的教案 → `$SKILL_ROOT/references/教案参考/`
- 教师平时使用的练习、试卷、课堂检测、错题材料 → `$SKILL_ROOT/references/练习参考/`
- 课程标准 → `$SKILL_ROOT/references/课标/`（只读，不往里添加）

文件名只使用已经确认的信息。年级、学科、上册/下册如果能从材料或教师说明中确认，应尽量保留，如 `四年级数学下册_营养午餐.md`；如果只确认了学科和课题，可写 `数学_营养午餐.md`；如果只确认课题，就写 `营养午餐.md`。教材版本、出版社、页码只有在材料或教师明确提供时才写入文件名或正文；不要根据课题、图片内容、相似教材或常识补全"人教版""西师大版""第 X 页"等信息。

只要成功识别出课本照片、截图、扫描版 PDF 或图片型材料中的内容，必须先完成持久化，再继续生成。不能只写处理汇总，也不能只引用临时整理稿。

持久化完成标准：

1. 在对应目录下新增或更新 `.md` 文件。
2. 文件内容包含课题/知识点、原文/题目、插图教学含义、材料用途分类。年级、学科、上册/下册能确认就保留；教材版本、出版社、页码等扩展元信息只有在材料或教师明确提供时才写入。不确定就省略或标注"未确认"。
3. 如果无法从材料或对话中确认关键元信息，先问教师确认，不要自己猜文件名或在正文中补全。
4. 保存后用 `ls` 或 `test -f` 验证目标 `.md` 文件确实存在。
5. 对话中告知教师保存到哪个绝对路径，再基于该 `.md` 继续生成。

如果没有通过文件存在性验证，禁止说"已存入""下次自动参考"等完成性表述；应说明保存失败并先修正问题。

关键提取要点：

- 文字如实转录（例题、情境、引导语、做一做题目）
- 图片用文字描述其**教学含义**，不只描述外观（如"14×12 点子图，虚线分成 10 行和 2 行，表示拆分计算"）
- 对话中发来的照片不会留存，提取务必完整
- 大量材料（整本教材）不要全部处理，先问教师要备哪一课，只处理相关几页

### 元信息保守原则

材料元信息按"能确认就保留，不能确认不补全"处理。处理时遵守：

1. **有证据才写**：只有材料页面、文件正文、用户说明或已审核参考明确出现，才写入正文、标题、文件名或输出文档。
2. **基础元信息尽量保留**：年级、学科、上册/下册如果能确认，应保留，方便后续检索和匹配。
3. **扩展元信息更谨慎**：教材版本、出版社、页码必须有明确证据才写；不能因为课题像某个教材内容，就补成"人教版/西师大版/第 X 页"。
4. **不从局部内容概括完整身份**：例如材料只显示"综合与实践"或"营养午餐"，就只写已确认的课题/栏目，不扩写成未确认的年级、册次或教材版本。
5. **不确定就留白**：无法确认的信息不要写；必要时写"未确认"或提示教师补充。

### Markdown 输出通用规则

**Markdown 输出中禁止使用 HTML 标签**（`<br>`、`<br/>`、`&nbsp;` 等），所有格式通过 Markdown 语法实现。
